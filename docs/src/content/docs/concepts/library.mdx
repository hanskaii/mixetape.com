The library holds content that is made but not sent out yet: a set of files from
[storage](/concepts/media) with the title, caption, description and metadata written for
them. An agent that renders a week of videos can file each one as it is done; you see them in
the workspace under **Library**, and send each to brands and channels when it is ready.

## Content items

`create_item` takes `fileIds` (ready files, in order — a carousel's order, say), `title`,
`caption`, `description` and `metadata`. `metadata` holds what every platform shares and, under
`platforms`, each platform's own overrides:

```json
{
  "title": "Why Rome burned",
  "caption": "The night Rome burned, and who got blamed.",
  "fileIds": ["9f3c…"],
  "metadata": {
    "tags": ["history", "rome"],
    "platforms": {
      "youtube": { "title": "Why Rome Burned in 64 AD", "privacy": "public" },
      "instagram": { "caption": "Rome, 64 AD 🔥" }
    }
  }
}
```

Whatever a platform does not override comes from the shared fields, so a YouTube title can
be longer than an Instagram caption without writing everything twice.

`update_item` changes only what it is given. Metadata merges field by field, platform by
platform; `null` clears a field or a platform's overrides. `fileIds`, when given, replaces the
files and their order. Every item records whether an agent or a person made it.

## Sending it out

`plan_item` takes brands (`brandIds`) and channels (`accountIds`) and answers for every channel
they cover whether the item can go there and exactly what would be posted:

- `format` — `video`, `image` or `carousel`;
- `problems` that stop it — a platform that takes no images, more files than its carousel
  holds, a Pinterest Pin without `boardId`, a channel to reconnect;
- `warnings` that do not — a horizontal video for Reels;
- the `caption` and `metadata` the post would carry.

Each channel gets the item's caption; the shared metadata fields its platform knows; the item's
title and description where the platform has them (YouTube, Facebook, Pinterest); then that
platform's overrides. A `caption` override on a platform without a caption field of its own
(YouTube, Threads, TikTok…) replaces the caption there.

`schedule_item` (permission `publish`) then creates one post per channel that can take it, all
at `scheduledAt`, and skips the rest with their reasons. The posts are ordinary posts —
editable and cancellable until they go out — linked back to the item: `get_item` lists them,
and `list_posts` takes `itemId`.

In the workspace, **Schedule** on a content item does the same, showing the plan as you pick
brands and channels.

## Brands

A brand is your own group of connected channels — "Hans Explainer" as its YouTube channel and
its Facebook Page, say — so content can go to the brand rather than channel by channel. A
channel can belong to several brands; disconnecting it takes it out of them.

`create_brand`, `update_brand` and `delete_brand` need the `channels` permission;
`list_brands` needs only `read`. In the workspace, brands are under **Channels**.
